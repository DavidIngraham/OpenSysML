- **A keyword only the other language reserves is a name wherever a name stands.** `step`, `expr`, `inv`, `class`, `feature`, `chains`, `type` and the other literals of `KerML.xtext` that `SysML.xtext` does not spell are ordinary names in a `.sysml` file, and SysML's own literals (`action`, `part`, `attribute`, `snapshot`, …) are names in a `.kerml` file; before this, a `.sysml` file reading `attribute step : Real;` could declare the attribute but not use it — `assert constraint { step <= upperBound }` was parsed as a KerML step declaration and reported `expected an expression`, and `step < upperBound` as a short name missing its `>`. The parser now reads such a word as a name before an operator, a `:`, a `;`, a `=`, a `[`, a `)`, a `}`, a `,`, a `.`, a `::` or a `(`, in both notations, and keeps the keyword only where a named declaration of the other notation follows it (`step s;`, `feature redefines x;` in a `.sysml` file; `action a;` in a `.kerml` one), which the `kerml-notation` warning and the `SysML notation` error continue to report. Before a body or a multiplicity the word is the name as well: `step { }` and `step [1];` declare keywordless usages, and an anonymous KerML declaration such as `inv { x > 0 }` or `connector [1] a to b;` is now a parse error in a `.sysml` file, as in the pilot, rather than a `kerml-notation` warning. The LSP semantic tokens follow the same reading, so `step` in `step <= upperBound` is no longer highlighted as a keyword.
